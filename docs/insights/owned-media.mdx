# Understanding Owned Media & Content Labels

After connecting your Owned Media accounts, frndOS pulls in your posts with default metrics (views, comments, likes, shares). But to truly understand **which campaigns drove what performance**, you need to add **content labels**.

This is one of the most powerful features in Insights — and it's what unlocks campaign-level reporting, content pillar analysis, and funnel funneling.

## Why Tag Your Posts?

By default, Owned Media gives you raw post data. With tagging, you can:

- **Filter posts by campaign** — see all posts from Campaign X across platforms
- **Analyze by content pillar** — which pillar is performing best?
- **Group by objective** — awareness vs. consideration vs. conversion content
- **Build campaign reports** — automatically aggregate metrics for tagged campaigns

> **Standard recommendation:** Most brands tag at minimum by **Campaign**, **Content Pillar**, and **Objective**. These are the building blocks for proper funnel reporting.

## How Tagging Works

Tagging in Owned Media has two layers:

1. **Attributes** — the labels themselves (e.g., "Campaign", "Pillar", "Objective")
2. **Values** — what each post gets tagged with (e.g., Campaign = "Summer Launch")

You define attributes once, then apply them to posts.

## Defining Custom Attributes

### Step 1 — Open Attribute Settings

1. Navigate to **Insights → Owned Media**
2. Click **Label Posts** above the **Content Posts** table
3. Open **Attribute Settings** and click **Add new attribute**

### Step 2 — Configure the Attribute

Set up the new attribute:

| Field | Description |
|---|---|
| **Name** | The label name (e.g., "Pillar", "Campaign", "Objective") |
| **Default Value** | Optional starting value applied to new posts |
| **Type** | `Single Select` or `Multi Select` (with defined options), or `Text` (free-form) |

For **Single Select**, define the available options:
- *Pillar 1, Pillar 2, Pillar 3* — values users can pick from
- *Awareness, Consideration, Conversion* — for an Objective attribute

For **Text**, users can type anything per post.

### Step 3 — Save

The new attribute appears as a new column in the Owned Media post table.

## Key Columns & Metrics

The Owned Media post table includes these standard metric columns:

| Column | Description | Notes |
|--------|-------------|-------|
| **Post** | Thumbnail, caption, platform icon, date | |
| **Sentiment** | Majority sentiment (positive/neutral/negative) with count tooltip | See [Sentiment Analysis](./sentiment-analysis) |
| **Format** | The post's format, shown as an icon. Hover it for the name | Filter and group by format to compare, say, Reels against Carousels. See [Format icons](#format-icons) |
| **Impressions** | Total impressions | |
| **Reach** | Unique accounts reached | Facebook and YouTube don't report it and show "—" (see [Reach on Facebook and YouTube](#reach-on-facebook-and-youtube)) |
| **Likes** | Total likes | |
| **Comments** | Total comments | |
| **Shares** | Total shares | |
| **Clicks** | Link clicks (Facebook only) | New — other platforms don't expose per-post click data; those rows show "—" |
| **ER (%)** | Engagement Rate — total engagements ÷ reach | Uses the platform's own engagement total, which **includes saves** |
| **Views** | Video views | Counted differently per platform — see below |
| **Saves** | Times the post was saved | Instagram reports these; Facebook and YouTube show "—" |

### Video and Instagram metrics

More columns sit after **Saves**. Most are platform-specific, and a dash means *that platform doesn't report it* — never that the number is zero.

| Column | What it is | Which platform |
|---|---|---|
| **New Follows** | Follows the post drove | Instagram |
| **Reposts** | Instagram reposts — a different action from **Shares**, which stays its own column | Instagram |
| **Avg Watch Time** | Mean watch time per viewer, in seconds | Instagram Reels |
| **Total Watch Time** | All watch time added up, in minutes | Instagram Reels |
| **3s Skip Rate (%)** | Share of views that skipped inside the first 3 seconds | Instagram Reels |
| **Retained Views (3s, est.)** | Views that did **not** skip in the first 3 seconds | Instagram Reels |
| **3s Retention (est. %)** | The same thing as a percentage | Instagram Reels |
| **3s VTR (%)** | 3-second view rate — views ÷ impressions | Facebook video only |
| **Completion Rate (%)** | Share of views that watched to the end | TikTok |
| **Duration** | Video length (m:ss) | All except Instagram |

> **"Retention" and "Completion" are not the same thing.** **3s Retention** means *didn't bail in the first three seconds* — someone who watched 4 seconds of a 60-second reel counts as retained. **Completion Rate** means *watched to the end*. They come from different platforms and measure different things, so don't read one as the other.

> **"est." is doing real work.** **Retained Views** and **3s Retention** are calculated from the skip rate, not counted directly — the platform doesn't publish the underlying count. Facebook's **Views** column *is* a measured ≥3-second count, so comparing the two across platforms is comparing an estimate with a measurement.

> **Views mean different things per platform.** Facebook counts a view at ≥3 seconds, TikTok at 0 seconds, YouTube at around 10. Safe to compare **within** a platform; misleading across them.

> **A dash is not a zero.** Where a platform declined to measure something, the cell shows `—`. Rendering it as 0 would sort the least-measured post as the worst-performing one.

> **A rate only appears where it applies.** A post with no video shows a dash for **3s VTR**, not `0.0%` — claiming none of its impressions became a 3-second view would be a measurement of a video that doesn't exist.

> **Engagement totals include saves.** ER is calculated from the platform's own engagement figure rather than adding up likes + comments + shares, because that sum leaves saves out — and on Instagram saves are often the largest component. Totals that previously read as zero on content lists now display correctly.

### Reach on Facebook and YouTube

Facebook and YouTube don't report reach per post. Their rows used to show a reach of `0`, which read as a real result. They now show `—`, like any other metric a platform doesn't measure.

In the post table, **ER (%)** is worked out against reach, so it also shows `—` on those rows.

Brand-level reach numbers count only the platforms that do report reach:

* **Total Reach** and the reach rate leave Facebook and YouTube out
* For Facebook and YouTube, the **Avg. Reach Per Post** figure and the **Reach** row in the platform metrics are left out rather than shown as zero
* A brand whose only owned accounts are Facebook or YouTube shows `—` for **Total Reach**

> **Heads-up:** this can move your brand's Total Reach. If a brand used to count Facebook "reach", its total now leaves that out, because that number was never a reach measurement.

### Totals rows are recomputed, not averaged

The totals row under a rate column isn't the average of the rates above it. Rates are recomputed from the underlying counts, weighted by views — so a post with 40 views doesn't count as much as one with 400,000. Averaging the per-post rates instead can be several times wrong, in the flattering direction.

### Opening a single post

Click any post row to open its **detail view**:

- The creative itself, full size
- Its title and meta lines, including the post's **Format** icon
- **Link to post** — opens the original on the platform
- Every metric with a **typical** value beside it, plus a benchmark score with a quartile band: **Top 25%**, **Above Avg**, **Below Avg**, or **Bottom 25%**
- An **Export metrics as CSV** button

Paid ads open the same way from the paid tables — see [Connecting Paid Media](./connecting-paid-media).

### Format icons

**Format** used to be called **Content Format**, and showed the name as text. It now shows one icon per format, with the name in a tooltip when you hover. The same icon appears in the Content Posts table, in a post's detail view, and in the **Label Posts** table.

The formats are **Reels**, **Story**, **Short**, **Carousel**, **Image**, **Video**, **Live**, **Text** and **Other**. A format frndOS has no icon for shows the **Other** icon, but its tooltip still gives the post's own format name. A post with no format shows a dash.

### Filtering by Format

Use the **Format** filter above the table (it starts on **All formats**) to narrow down to specific formats. Combined with other filters (Campaign, Pillar, date range), this helps you compare performance across content types. For example: "Show me all Reels from Campaign X."

The filter only appears once your posts carry a format.

### Grouping Posts

**Group by** in the table toolbar puts posts under group headers. You can nest up to three levels: the first field is the outermost group.

Open it to see **Group by fields**:

1. Click **Choose field** and pick a field. Fields are listed under headings such as **Post**, **Date** and **Label attribute**
2. Click **Choose field** again to nest another level inside it
3. Drag a level by its handle to reorder it, or focus the handle and use ↑ / ↓
4. Click **×** on a level to remove it. Removing every level ungroups the table

Each level has its own order:

| Field kind | Order choices |
|---|---|
| Text (format, a label) | **A → Z** or **Z → A** |
| Dates | **Newest → Oldest** or **Oldest → Newest** |
| A fixed order, such as label status | **Default** or **Reversed** |

On the Content Posts table you can group by **Format**, **Year**, **Month**, **Week**, and any label attribute that's a **Single Select**. Multi Select labels aren't offered, because one post would belong to several groups.

Once grouped, the button reads **Group by: Format › Month**. Each group header shows its name and how many posts it holds. Click a header to collapse or expand it. Months read like **June 2026** and weeks like **Week of 1 Jun 2026**. Posts with no value for a level go in a last group named **Unknown**.

A fourth level isn't allowed. **Choose field** then says **Up to 3 levels**, and a toast explains: _"Group by supports up to 3 levels"_.

The other benchmark tables that offer **Group by** use the same panel, and so does **Label Posts** (see [Grouping in Label Posts](#grouping-in-label-posts)).

### Clicks Column

The **Clicks** column measures link clicks on Facebook posts. It is **Facebook-only** — Instagram, TikTok, and YouTube don't expose a comparable per-post metric, so those rows show a dash (`—`).

> **Tip:** Use Clicks alongside Format to compare which formats drive the most link traffic. You may find that Carousels outperform Reels on click-through even while Reels generate more impressions.

## The Playbook

The **Playbook** card on Owned Media reads your labelled posts and says what works and what doesn't, with the numbers behind it. A brand has one playbook. It has a chapter per objective (**Awareness**, **Consideration**, **Conversion**), and a chapter per content pillar if the brand has a **Content Pillar** or **Pillar** label.

The playbook doesn't update on its own: you create it once, then refresh it when you've posted more. Creating and refreshing need write access to Owned Media. Without it you can read the playbook but not change it, and you only see the card once a playbook exists.

### The card

The card shows two panels side by side, **What's working** and **What's not working**, with one line per chapter: the strongest lesson on that side. A chapter without enough posts reads _"Not enough posts yet"_. Hover a cut-off line to read all of it.

Above the panels:

* **By objective** / **By pillar** switches the card between objective chapters and pillar chapters. It only appears when the brand has pillar chapters; otherwise the card is headed **All owned content**
* When it was made, for example **Generated Oct 8 · last 30 days**
* **View playbook** opens the full playbook

By pillar, the card lists three pillars (those with enough posts first) and ends with **+N more pillars in the playbook**.

### Reading it

**View playbook** opens the playbook over the page, headed **Playbook**: _"What works and what doesn't, from the hook to the call to action, for each objective and pillar."_ It opens on the tab the card was showing, and **By objective** / **By pillar** switch tabs here too.

**At a glance** gives one line per chapter: its main finding, or why it has none yet (for example **Needs more labelled posts**, **Not read yet**, **Too few recent posts**, **Reading your posts…**).

Each chapter then has:

1. **Ranked by**: the objective's score (for example **Awareness score**), or **Reach and engagement** for a pillar. **How posts were picked** opens the weights behind the ranking: _"Every post got a score built from the things below. The 3 highest are the top posts and the 3 lowest are the bottom posts. A bigger percentage counted for more."_
2. A short summary
3. **The 6 posts studied**: **Top posts** and **Bottom posts**, three each, each thumbnail showing the metric the chapter ranks on
4. **What's working and what's not**: the lessons, with a count. The first is open; **Expand all** opens the rest

Each lesson is written as an instruction, tagged with the part of the post it's about (**Hook**, **Visual**, **Copy**, **Story**, **Format** or **Call to action**). Open it to see what the top posts did (✓) and what the bottom posts did (✗), each with the posts that show it (some lessons have only one side), then why it matters and how to apply it to a **Video**, **Image** or **Carousel**. A **Copy** lesson quotes the captions. Hovering a lesson highlights its posts among the six.

A chapter read on an earlier date than the rest says so under its title, for example **Read Oct 3 · last 30 days**.

The ticks on the right edge are the outline. Hover them to see every chapter and lesson section, and click one to jump there.

At the top of the playbook:

| Control | What it does |
|---|---|
| **Refresh** | Reads your posts again (see [Refreshing it](#refreshing-it)). Only with write access |
| **Share** | **Share with your team**: _"Anyone with access to this brand can open this playbook."_ **Copy link** copies a link that opens Owned Media with the playbook open |
| **More** | **Generate deck** and **Download PDF** |
| View | **Center** or **Full page** |

From a post's Creative Analysis, **View chapter** opens the playbook at that post's objective chapter.

### Generate deck

**More** → **Generate deck** closes the playbook, opens AskFRND, and asks frnd to build a presentation deck from it, one section per objective and pillar.

It only appears when your workspace has both the **Decking** and **Creative Playbooks** tools switched on (see [How AskFrnd Uses Tools](../askfrnd/tools)). If the chat can't start, a toast says _"Couldn't start the deck"_.

### Download PDF

**More** → **Download PDF** opens a print-ready page of the whole playbook, both objective and pillar chapters, and your browser's print dialog. Choose **Save as PDF** there. If nothing opens, your browser blocked the new window; allow pop-ups for frndOS and try again.

### On a shared dashboard

On a public share of the dashboard the playbook can be read, but not created, refreshed, shared or turned into a deck.

### Creating it

With no playbook yet, the card reads **No playbook yet**: _"Creating it reads your posts and writes all three chapters, Awareness, Consideration and Conversion, together. A chapter without enough posts fills in when you refresh."_

1. Click **Create playbook**
2. Under **How much history?**, pick **30 days**, **60 days** or **90 days** (30 is the default)
3. Click **Create**

**How should it stay up to date?** is marked **Coming soon** and can't be picked yet.

### Refreshing it

1. Click **View playbook** on the card
2. Click **Refresh** at the top of the playbook
3. Pick how much history to read, then click **Refresh**

The dialog warns: _"This reads your posts again and replaces the current playbook. It uses AI credits."_

A refresh rewrites the three objective chapters, plus each pillar chapter that already has enough labelled posts.

While it runs, each chapter shows **Waiting**, **Reading…**, **Done**, **Not enough posts**, **Out of AI credits** or **Couldn't finish**. _"This can take several minutes. You can close this window; the playbook keeps updating."_

The card and the playbook show when it was made and over how much history, for example **Generated Oct 8 · last 30 days**.

### When it needs a longer history

A chapter needs at least 6 labelled posts in the window. When no chapter could be written because the window was too short, the dialog stays open and says so: _"Not enough labelled posts in the last 30 days. Try a longer history."_ Click **Change history** to go back and pick 60 or 90 days. At 90 days there's no longer window to offer, so only **Close** remains. If some chapters were written and others came up short, the dialog closes and the short ones say so in the playbook.

Inside the playbook, a chapter says what happened to it:

| What you see | What it means |
|---|---|
| _"Not enough posts in the last N days to refresh this chapter. Showing the previous version."_ | The refresh came back short. The older version stays |
| _"Too few of its labelled posts are from the last N days. Try a longer history."_ | The chapter has never been written. Refresh with more history |
| _"There aren't enough posts labelled X to learn from yet."_ | Label more posts first. It shows how many are labelled, for example **4 of 6 posts labelled** |
| _"N posts are labelled X, enough to read. Refresh the playbook to write this chapter."_ | The chapter is ready. Refresh to write it |
| _"Couldn't refresh this chapter."_, _"Couldn't create this chapter."_ or _"Your workspace is out of AI credits. Ask an admin to add more."_ | Click **Try again** once it's sorted |

## How Posts Get Ranked

Where frndOS ranks posts — a Creative Playbook's top and bottom picks, or a per-post analysis — it shows the **weights behind the ranking** rather than leaving you to guess.

### Ranking follows the objective

A playbook is generated **against an objective** — **Awareness**, **Consideration**, or **Conversion** — and the metrics it weighs are the ones that match it. Chasing conversions is not the same job as building reach, so the same posts rank differently under a different objective.

The playbook's name carries all of it: objective, scope, and time window — e.g. `awareness · Promo · 30d`. A playbook with no grouping dimensions is named for its whole pool instead: **All owned content**.

Time windows: **Last 30 days**, **Last 60 days**, **Last 90 days**. A different window is a different playbook, even for the same filter.

> **Rankings use base metrics too, not only derived rates.** A rate alone can flatter a post nobody saw; the counts underneath it are what say whether the reach was real.

A panel headed **How this playbook scored its top and bottom posts** lists each scoring metric with its percentage, heaviest first, then explains the method:

> _"Each metric is scored as a percentile within the pool, then weighted — so posts are compared against each other, not against a fixed target."_

Where a metric comparison table follows, it adds: _"Metrics outside this list are shown below for context but did not affect the ranking."_

> **The weights are computed, not fixed.** They're derived from the posts actually scored. If a pool doesn't fully report a metric, that metric drops out and the remaining weights grow to fill the gap — so the same brand can see different percentages on different playbooks.

### The comparison table

A per-post analysis compares the post against its pool: **This post** · **Pool avg** · **vs avg**, ordered best to worst.

Underneath, the table states the basis it used:

- Raw counts scale with audience — a post reaching 3× the pool average also gets roughly 3× the likes — so a high count reflects distribution, while the matching **rate** shows whether the creative earned it.
- **ER%** is measured against impressions (falling back to views, then reach); **3s VTR** against views; save, share, comment, like and follow rates against reach.
- Scoring is **Instagram-only** for now.
- **3s VTR** and watch time are **Reels-only**, so they count towards the ranking only when every post being compared reports them.

Some rows are shown **for context only** and had no effect on the ranking — comment rate and like rate always, plus click rate, completion rate, and average % watched where the platform reports them. The weights panel above the table is what names the metrics that *did* count.

## Analyzing Posts With AI

Instead of tagging by hand, you can have AI read your posts and suggest labels. Select posts and click **Analyze with AI**.

### It asks before it spends

Analyze is a **paid action**, so it never fires on a single click. A confirmation opens first, with two panels:

| Panel | Shows |
|---|---|
| **Scope** | How many posts — _"N selected posts"_ or _"N unanalyzed posts"_, with the oldest post's date |
| **Estimated cost** | `~N credits`, and your **workspace balance before → after** |

The confirm button names the job: **Analyze 42 posts**.

> **The estimate is deliberately an estimate.** _"Billed on what the AI actually reads, so the final cost is usually lower than this estimate. Analysis runs in the background — you can keep working."_ Every figure with a `~` is a quote, not an invoice.

> **It bills the workspace pool**, not your personal allocation — which is why the balance shown is the workspace's.

### Not enough credits

If the estimate exceeds the balance, the cost panel turns red and states the gap: **Short by N credits**.

| You are | What you see | Button |
|---|---|---|
| An admin with billing access | _"Analyze fewer posts, or top up your workspace to continue."_ | **Top up credits** |
| Anyone else | _"Analyze fewer posts, or ask a workspace admin to top up."_ | **Request credits** |

### While it runs

Analysis runs in the background — switching tabs or leaving the page doesn't strand it, and billing settles from actual usage when it finishes.

The button is unavailable in two situations, and the tooltip says which: **All posts analyzed**, or **An analysis is already running**.

In **Label Posts** it's also unavailable while more than one account is ticked: _"Analyze runs on one account at a time. Check a single account to analyze."_

## Applying Tags to Posts

Click **Label Posts** above the **Content Posts** table. Labelling opens full screen over the page, titled **Label Post**, so you can label without leaving the dashboard.

The header counts what's left: _"Total N posts · X need labels"_, or **All labelled** once every post is done. A post counts as done when every label switched on in your attribute settings is filled (Format doesn't count). A partly labelled post shows an **N out of M** pill.

Switch between table and grid view, and use the search to find a post by name, tag or caption.

### Picking accounts

The account picker at the top lists your **Core Connections** and **Extended Connections**. Every Core connection is ticked when you open it. Tick or untick accounts, and the button reads the account's name, or **N accounts** when several are ticked.

Every ticked account loads, all in one table. The table shows who posted each post in its **Author** column: the account's avatar and name, or a row of avatars for a collab post. In grid view the avatar sits on each card, with the platform logo on it. The **Format** column shows each post's format icon.

### Grouping in Label Posts

The toolbar has **Sort**, **Group by**, **Filter** and **Analyze with AI**. **Group by** uses the same panel as the Content Posts table (see [Grouping Posts](#grouping-posts)), up to three levels, with these fields:

| Field | Offered when |
|---|---|
| **Account** | Two or more accounts are ticked |
| **Label status** | At least one label is switched on. Groups are **Not labelled**, **Incomplete**, **Labelled** |
| **Format** | Your posts carry a format |
| **Published year**, **Published month**, **Published week** | Always |
| Each **Single Select** label | It's switched on |

With two or more accounts ticked, posts are grouped by **Account** until you change it. Once grouped, the button reads **Grouped by** and the levels, for example **Grouped by Account › Label status**.

Each group header shows how many posts it holds and how many still need labels (**N need labels**, or **All labelled**). Account headers also show the platform icon and a **Core** or **Extended** tag. Posts without a value for a level go in a last group, such as **No value**, **No format** or **Unknown date**.

If you untick down to one account, the **Account** level drops out. It comes back when you tick a second account again.

### Method 1 — Tag Individually

1. Click the attribute cell on the post's row
2. Select or type the value

Click a post to open its details: its **Performance Details** and a **Tagging** panel where you can set every label in one place.

### Method 2 — Bulk Tag

For tagging many posts at once:

1. Select posts with their checkboxes (**Select all (N)** takes every post)
2. In the bar that appears, pick the attribute and value to apply
3. Confirm. A toast says how many posts were labelled

> **Heads-up:** **Label Posts** needs write access to Owned Media. Without it the button isn't shown.

Example: Select all posts from August, bulk-tag them with `Campaign = Summer Launch`.

## Filtering by Tags

Once posts are tagged, the **Filters** button in the Owned Media header is how you narrow the numbers to the posts you mean. It replaces the separate **Owned accounts** and **Labels** pills: both now live in one panel, laid out like the Paid Media filters.

The panel has two sections:

* **Accounts** — which connected owned accounts the page reads. Shows **All accounts** until you narrow it.
* **Labels** — a rule builder rather than a flat checklist, so you can combine conditions. Hidden if you only have view access.

As you build, the panel previews how many posts the rules match before you commit, reading `N of M posts match`. You'll see **Counting matching posts…** while it works, and it starts from _"Add a label filter to preview how many posts match"_. The count already uses the accounts you've picked in the same panel.

Nothing changes on the page until you click **Apply**. The button shows how many changes are waiting, for example **Apply (2)**. **Clear** resets both accounts and labels. When filters are on, the **Filters** button shows how many.

> **An unfinished rule isn't applied.** If a rule is missing a value the panel says so, reading **Finish 1 rule to apply**, so a half-written condition can't silently change your numbers.

Once posts are tagged, you can filter in powerful ways:

### Filter by Specific Value
*Example:* Show me all posts where `Campaign = Summer Launch`.

### Filter by "Not Empty"
*Example:* Show me only posts I've already tagged with a campaign (excludes untagged posts).

### Combine Filters
*Example:* `Pillar = Pillar 1` AND `Campaign = Summer Launch`.

This is how you turn raw post data into campaign performance reports.

## Recommended Tag Structure

While you can define any attributes, certain labels are **strongly recommended** because they're useful across all brand reports:

| Tag | Type | Why It Matters |
|---|---|---|
| **Campaign** | Single Select | Group posts under named campaigns |
| **Content Pillar** | Single Select | Analyze performance by brand pillar |
| **Objective** | Single Select | Map content to funnel stages (Awareness / Consideration / Conversion) |
| **Sub-Campaign** | Single Select | Optional drill-down for big campaigns |

> **Why these specifically?** They map directly to standard report structures (campaign reports, content pillar analysis, funnel reports). If you skip them, you lose the ability to build those views.

## Working with Tags Across Time

### Retroactive Tagging

You can tag historical posts. Just open the post and apply the tag — useful for organizing pre-frndOS content that's been pulled in.

### Some Old Posts May Have Missing Data

Posts from before your initial connection may have **incomplete metrics** (e.g., missing views for static posts or carousels). This is a data source limitation, not a tagging issue. Tags still apply normally.

## FAQ

**Q: Why is a metric column all dashes for my brand?**
That platform doesn't report it. Several columns are Instagram-only, one is Facebook-only, and Completion Rate is TikTok-only — a brand without those accounts sees dashes, which is correct rather than broken.

**Q: Why does Reach show a dash on my Facebook and YouTube posts?**
Those platforms don't report reach per post. A dash means "not measured". The `0` they used to show was not a real reach figure.

**Q: Our Total Reach dropped.**
It now counts only platforms that report reach, such as Instagram and TikTok. Facebook and YouTube are left out instead of adding a number that wasn't reach.

**Q: Is a dash the same as zero?**
No. A dash means the platform didn't measure it. A zero would be a claim that the thing was measured and came out at nothing.

**Q: Completion Rate and 3s Retention look like they should match.**
They measure different things on different platforms — "watched to the end" (TikTok) versus "didn't skip in the first three seconds" (Instagram). Don't compare them directly.

**Q: The totals row doesn't match the average of the column.**
It isn't meant to. Rates are recomputed from the underlying counts and weighted by views, because averaging per-post rates would let a 40-view post count as much as a 400,000-view one.

**Q: Engagement was showing as zero on my content list.**
Fixed. ER now reads the platform's own engagement total, which includes saves — the older derived sum omitted them and understated Instagram posts.

**Q: Why does a photo post show a dash for 3s VTR instead of 0%?**
Because there's no video on it. A 0% would assert that thousands of impressions failed to become a 3-second view of something that was never there.

**Q: A Facebook post shows an absurd Duration.**
That row hasn't been reprocessed since the fix that corrected the unit. It means "not backfilled yet", not "long video".

**Q: Why is Duration always blank on Instagram?**
Instagram doesn't expose a per-media duration, so there's nothing to show.

**Q: Why does Analyze with AI ask me to confirm now?**
It spends credits. An accidental tick-and-click would have charged you with no way out, so the cost and scope are shown first.

**Q: I was charged less than the estimate said.**
Expected. The estimate is quoted up front; the charge is computed from what the AI actually read, which is usually less.

**Q: I switched tabs mid-analysis — did I lose the batch?**
No. It runs in the background and settles its billing when it completes.

**Q: Where do the ranking weights come from?**
They're derived from the posts actually scored, not from a fixed table — which is why they differ between playbooks.

**Q: The same post ranks well in one playbook and badly in another.**
Check their objectives. An awareness playbook and a conversion playbook weigh different metrics, so they legitimately disagree.

**Q: A metric is in the comparison table but not in the weights panel.**
It's shown for context and had no effect on the ranking. The weights panel is the definitive list of what counted.

**Q: Where did the Content Format column go?**
It's now called **Format**, and shows an icon instead of text. Hover the icon for the format's name.

**Q: Label Posts only showed one account before. Has that changed?**
Yes. Every account you tick in the picker loads, in one table, and the **Author** column says whose post each one is. Group by **Account** to keep them apart.

**Q: Why is Analyze with AI greyed out in Label Posts?**
If more than one account is ticked, it is. Analysis runs on one account at a time, so tick a single account to analyze.

**Q: Why can't I group by one of my labels?**
Only **Single Select** labels that are switched on can group posts. A Multi Select label would put one post in several groups.

**Q: My playbook says it needs a longer history.**
Too few labelled posts fall inside the window you picked. Refresh the playbook and choose 60 or 90 days, or label more posts first.

**Q: Where did the Owned accounts and Labels pills go?**
They're combined into one **Filters** button in the Owned Media header. Open it to pick accounts and build label rules together, then click **Apply**.

**Q: What's the difference between Attributes and Tags?**
- **Attribute** = the label category (e.g., "Campaign")
- **Tag** = the actual value applied to a post (e.g., Campaign = "Summer Launch")

**Q: Can I edit or delete an attribute later?**
Yes. But deleting an attribute removes all associated tags from posts. Edit with caution.

**Q: In bulk tagging, an attribute's list opened but no value could be picked. Is that fixed?**
Yes. The attribute pickers in the bulk bar work inside **Label Posts** now, so the labels apply.

**Q: Can I bulk-tag posts that span multiple platforms?**
Yes. Tags apply to posts regardless of source platform (Facebook, Instagram). You can bulk-tag a mixed selection.

**Q: Do tags sync automatically across team members?**
Yes. Tags are stored per brand, so any team member with brand access sees the same tags.

**Q: Are there any default labels?**
Currently, all attributes are custom. There's discussion about making Campaign, Content Pillar, and Objective **standard defaults** in the future — but right now you'll need to create them yourself.
