# The Study Page

A finished [Proposal Scorecard](./proposal-scorecard) opens on one page with three parts: **Ask frnd** on the left, the **Scorecard** in the middle, and **The file** (the work that was scored) on the right. Ask a question, read the verdict, and see exactly which page each finding is about, without switching tabs.

## The Three Parts

| Part | What it holds |
|---|---|
| **Ask frnd** | The study's own chat. Ask about this scorecard, or tell it what to change. Once there is a result, it suggests **Why is the lowest score low?**, **What would make it ready?** and **Summarise this for the client** |
| **Scorecard** | The answer and what to fix first, as described in [Proposal Scorecard](./proposal-scorecard) |
| **The file** | The scored file as pages. Each finding is a pin on the page it cites |

The chat is disabled until the study has launched, with _"The chat opens once the study has launched."_

Drag the divider between **Scorecard** and **The file** to resize them. Your width is remembered. Fold the chat away with its collapse button, and bring it back with **Show Ask frnd**. This is remembered too.

On a narrow window (under about 1100 pixels) one part shows at a time behind a switcher: **Results**, **The file** and **Ask**. It opens on **Results**.

### Findings and pins

Click a finding in the scorecard and the file scrolls to its pin. Click a pin and the scorecard scrolls to the finding. On a narrow window, the page switches to the part where the other side lives.

A legend under the pages says what the pins mean, and shows only the kinds this file has: **Problem**, **Watch**, **Works** and **Fix**. Use the left and right arrow keys to move between pages.

### Focus on the file

Want to read the pages without the rest? Click the focus button in the file's header, or press **F**. The file takes the screen, and a thin rail stays on its left with the score. Press **Esc**, or the button again, to leave.

* For a proposal the rail shows Fit and Ambition. For other work it shows the overall score out of 100
* The rail's results button opens a menu: **Top fixes**, each one jumping to its pin, and **Show all results**

Focus is available on a wide window, and your choice is remembered per kind of study.

## Run History and Score Again

Every scoring of a study is a **run**. The header shows the run on screen, for example **Run 2**, and a run chip with the history.

* Open the chip to read an earlier run. The page then says _"You're looking at Run 1. It's read-only."_ with **Back to** the latest run. Score again, Add to deck and Compare with… are off while you read an older run
* Click **Score again** to make a new run of the same input. A toast says **Scoring again**: _"A new run has started. The earlier runs stay in the run history."_ The button is available once the study has finished, and while a run is going it shows **Scoring…**
* If the newest run failed, a chip reads **Run N failed · Try again**

**Score again** needs permission to change this brand's scorecards. A file scored in parts is re-scored part by part instead, as described in [Proposal Scorecard](./proposal-scorecard#re-scoring-one-part).

## Add to Deck and Export

The header's **Add to deck** and **Export** menus work on the latest run.

**Add to deck** has **New deck from this study**. It opens in a new tab when it is ready.

**Export** offers:

| Choice | What you get |
|---|---|
| **PDF report** | _"The scorecard as it reads here."_ |
| **Full review PDF** | _"Every fix with its reasons and pages."_ |
| **PNG of this view** | _"The panels as they are on screen."_ |
| **CSV** | _"Each dimension and check, with pages."_ |
| **Copy the fixes** | _"A checklist to paste into email or Lark."_ |
| **Client summary** | _"A one-page doc saved to Files."_ |
| **Compare with…** | See below |

The export names the run it is of, for example **Run 2**. The PDF-style exports are described in [Scorecard Reports and Rubrics](./scorecard-report-and-rubric#exporting-a-scorecard).

## Sharing a Study

Click **Share** in the header.

1. **Copy link** copies the link to the study itself. It opens only for people in this workspace who have access to the brand. If an older run is open, the link opens that run
2. **Create a view-only link…** makes a link anyone can read, with no frndOS account. Choose how long it works (**Link works for** 7, 14 or 30 days). Tick **Allow PDF download** if guests may download the PDF. Click **Create and copy**
3. The view-only page shows the scorecard and the file, never the chat

Afterwards the panel shows the link's state: which run it shows, when it expires (for example **Expires 21 Nov**), and **PDF download on** or **off**. **Stop sharing** turns the link off, and the link no longer opens.

### Letting a client approve

Tick **Let them approve or request changes** when you create the link, or switch it on a live link later. The shared page then shows **Request changes** and **Approve** in its header.

* A guest clicks **Approve**, or clicks **Request changes** and writes **What should change?** A name and email are asked, and a note is optional for an approval. They see **Sent to the team.**
* Their decision reaches the team that shared the study
* In the study header, a chip shows the latest decision, for example **Approved by Rina · 7 Nov** or **Changes requested by Rina**. Open it to see every decision with name, email, note, run and date

If you switch the option off, the link stops taking decisions (_"This link no longer takes decisions."_).

## Comparing Two Scorecards

Open the latest scored run of a whole file, then **Export → Compare with…**. A panel lists the brand's other finished scorecards, scored on the same rubric. Pick one and the page opens side by side.

* If there is none, it says _"No other finished scorecard of this brand was scored on the same rubric yet."_
* The page shows **Comparison** (the two scores lined up) and **Side by side** (the two files). The chat opens with **Which one do we run?**, **What should the weaker one borrow?** and **Summarise this for the client**
* A file scored in parts compares part by part on its own page, so **Compare with…** is not offered on the whole file

## FAQ

**Q: I don't see Score again.**
You need permission to change the brand's scorecards, the study must be finished, and you must be on the latest run.

**Q: Does Score again overwrite the old result?**
No. The new run is added to the run history and the earlier runs stay.

**Q: Can a guest chat with the study?**
No. A shared page is read-only: no chat, no re-scoring.
