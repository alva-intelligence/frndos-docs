# Project Rooms — Keeping Work Together

A **project room** is the page for one project: where it stands, the work made for it, its tasks and meetings, what frnd knows about it, and the people on it. All on one page instead of scattered across private chat histories and personal folders.

## Before You Start

1. ✅ **A project to open** — see [Creating & Managing Projects](./managing-projects)
2. ✅ **Edit access to the project** — viewers see everything but can't change it

## Opening a Room

Click **Projects** in the sidebar, then open a project. That page is the room.

Its URL is `/projects/folder/<id>`, or `/brands/<brand>/projects/folder/<id>` from a brand's projects.

## The Room Header

The header names the project and the brand it belongs to (or **Pitch · &lt;prospect name&gt;** for a project with no brand yet), with its status. Below the name sit the project's details, which you can change in place if you can edit the project:

| Detail | What it holds |
|---|---|
| **Type and stage** | What kind of project it is, and where it stands. Pick **No stage** to clear it |
| **Health** | **On track**, **At risk**, **Off track** or **Not set**, with when it was last updated |
| **Lead** | The person leading the project. Pick **No lead** to clear it |
| **Due** | The due date. With none set, the chip shows the proposal's deadline |

Each type has its own stages:

| Type | Stages |
|---|---|
| **Pitch** | Brief → Strategy → Concept → Pitch → Won / Lost |
| **Campaign** | Plan → Produce → Live → Report → Done |
| **Always-on social** | Plan → Create → Approve → Scheduled → Report, for each month |
| **Design job** | Brief → Draft → Review → Final → Delivered |
| **General** | To do → Doing → Done |

A pitch's stage can follow its proposal assistant's progress. Hovering the chip then says _"From the assistant's progress"_.

The header also shows the project's people, with **Share** (or **People** if you can't manage access), and one **New** menu.

> **Heads-up:** if you only have view access, a **Viewer · read-only** badge appears next to the title and every edit control is disabled with the tooltip _"You have view-only access to this project"_.

### The New menu

**New** creates something straight into this project:

* **Proposal assistant…** (start from a brief)
* **Deck**, **Deck from template…**, **Import PowerPoint or PDF**
* **Canvas**, **Resize**
* **Campaign report**
* **Upload files**
* **Task**, **Meeting**

The order depends on the project's type. Uploads are limited to 25MB per file.

> **The sidebar's Create files into the room too.** While you're in a project room you can edit, the sidebar's **Create** reads **Create · In &lt;project&gt;**, and what you make lands in the project.

### Dropping a brief

You can drop a file anywhere on the room. If it looks like a brief, the room asks _"This looks like a brief. Start a proposal assistant?"_ Click **Start assistant**, or **Just add to Work** to keep it as a file. Anything else uploads to the project.

## The Tabs

The room has four tabs: **Overview**, **Work**, **Tasks** and **Calendar**.

### Overview

The main column shows:

| Section | What it shows |
|---|---|
| **N new since you looked** | How much happened since your last visit. Click it to jump to the activity |
| **Key work** | The project's main files, with their covers. **All work →** opens the Work tab |
| **Assistants** | The proposal assistants running in this project, with their progress |
| **Updates & discussion** | The team's posts, updates and decisions, with what changed in the room. See [Updates & Discussion](#updates--discussion) |

In an empty project, Key work offers to start from the client's brief: _"Drop the client's brief anywhere on this page, or choose one."_

The rail on the right shows:

| Block | What it shows |
|---|---|
| **Next up** | The deadline, the next meeting, and the project's milestones |
| **Tasks · yours first** | Open tasks, yours on top. **All tasks →** opens the Tasks tab |
| **Meetings** | What's scheduled. **Calendar →** opens the Calendar tab |
| **Team** | The project's people. **Manage** opens the Share sheet |
| **Client side** | The client's decision-makers. See [The Client's Decision-Makers](#the-clients-decision-makers) |
| **Chats** | Up to five of the project's chats: yours and the shared ones |
| **What frnd knows** | Whether the project has sources, instructions, memory and meeting notes. **Manage** opens it (see [What frnd Knows](#what-frnd-knows)) |

## Updates & Discussion

**Updates & discussion**, last on the Overview, is where the team talks inside the room instead of in a side chat. It also lists what changed in the room (files edited, sources added, people added), grouped by day: **Today**, **Yesterday**, then the date.

### Writing to the team

Click **Write to the team…** and pick what to write:

| Kind | What it is | Who can write it |
|---|---|---|
| **Post** | A message to the team | Anyone who can open the room |
| **Update** | Where the project stands: a health, plus **Done**, **Blocked** and **Next**, and an optional **Note** | Editors |
| **Decision** | A decision, logged so the team and frnd remember it | Editors |

A post or decision needs some text. An update needs at least one of **Done**, **Blocked** or **Next**, or a note; until then it reads _"Add what's done, blocked or next"_. Click **Post**, **Post update** or **Log decision** (in a post, **⏎** posts and **⇧⏎** starts a new line).

Type **@** to mention someone who can open the room. They get a notification, and so does everyone in a thread when someone replies in it. Links in a post open in a new tab.

> **An update sets the project's health.** The health you pick in an update becomes the room's **Health**. You can also start one from the **Health** chip in the header: **Post an update…** opens the composer as an update on the current health.

### Replies, edits and filters

* **Reply** under a post starts or continues its thread. A thread shows its last two replies; **Show N more replies** opens the rest
* The **…** menu on your own post has **Edit** and **Delete**. An edited post says **edited**; a deleted one that has replies reads **Post removed**. The project owner can delete anyone's post
* **Everything** / **Decisions** switches between the whole stream and decisions only
* New posts from teammates appear as they're written. If you've scrolled down, a **N new posts** button takes you back to the top

A notification about a post opens the room at that post and highlights it. If it was deleted, a toast says _"That post is no longer here"_.

### What frnd picks up

When you ask frnd about the project, it knows the latest update (health, Done, Blocked, Next) and the last five decisions. A decision is also added to the project's memory (see [What frnd Knows](#what-frnd-knows)).

## The Client's Decision-Makers

**Client side**, in the Overview rail under **Team**, lists the people at the client who decide on the project. The list belongs to the project, not to one proposal: every proposal assistant in the room reads and edits the same list, so a person added in one proposal is there for the rest.

Each row shows the person's name, role and company, and what drives their decision. Click a row to open their profile:

| Part | What it holds |
|---|---|
| Influence | **High influence**, **Medium influence** or **Low influence** |
| **Background** | Their tenure, past companies, notable work |
| **What drives their decision** | What they weigh: cost, risk, brand fit, speed |
| **Hook that wins them** | The one line they'd say yes to |
| **Profiles** and **Sources** | Links to their public profiles, and the pages the profile came from |

A person with nothing filled in reads _"No profile yet. Research fills it in from public sources."_

### Adding and editing

If you can edit the project:

1. Click **+ Add decision-maker**
2. Under **Background check**, paste a LinkedIn or profile link, or a name and company, and click **Research**. It takes 15 to 30 seconds and fills in what it finds
3. Check the fields (**Name**, **Role**, **Influence**, **Background**, **What drives their decision**, **Hook that wins them**, profile links) and click **Add decision-maker**

On a profile, **Research** looks the person up again and replaces the fields it finds; **Edit** opens the same form. **Remove from project** asks to confirm, and removes the person from the whole project and every proposal in it.

Viewers can read the list but not change it. With no decision-makers yet, viewers don't see **Client side** at all.

> **frnd uses this list.** When you ask frnd about the project, and when a proposal assistant works, they read the room's decision-makers.

### Milestones

Milestones live under **Next up**. Click **+ Add milestone**, type a name, and optionally pick a date. Tick a milestone when it's done. Open milestones come first, and a long list collapses behind **Show fewer**.

### Work

**Work** lists everything in the project:

| Group | What it holds |
|---|---|
| **Assistants** | The proposal assistants, with a button to start another from a brief |
| **Decks, visuals and files** | Decks, key visuals and documents. **Add existing** pulls in work made elsewhere, and **New deck** makes one |
| **Uploads** | Files uploaded to the project. Removing one asks first, and it's permanent |

**Add existing** opens **Add existing work**, described as _"Pull a deck or studio file into &lt;project name&gt;."_ Search, tick what you want, then click **Add N to room**. Adopting a file is a link, not a move: removing it from the project never deletes the file.

### Tasks

**Open tasks** lists the project's tasks. Add one from the box at the top. These are the same tasks you see on the [Tasks](../workspace/tasks) page.

### Calendar

**Upcoming** lists the project's meetings, with who's invited. **Past · last 30 days** shows the ones already held.

## Asking frnd About the Project

Open AskFRND while you're in a project room and the panel shows a chip with the project's name. While it's there, your next new chat is filed in the project as a private chat (**Only you**): frnd works with the project's files, people and plans, and the chat doesn't show for the team. Remove the chip to send without it.

A chat that already exists is never moved into the project by the chip.

Chats from the room's **Chats** list open in the AskFRND panel.

## What frnd Knows

**What frnd knows** is the project's knowledge: the sheet that opens from **Manage** on the Overview rail.

| Part | What it holds |
|---|---|
| **Context** | Sources: files, pasted text, Lark links, meeting notes and research, each with its status (**Processing**, **Ready**, **Failed**…). **Add source** adds one |
| **Instructions** | Free text that tailors how frnd works on this project, for example _"always answer in Bahasa."_ It saves when you close the sheet |
| **Memory** | What frnd has built up from the sources |
| **Decisions and meeting notes** | Minutes and decision notes. **Add notes** adds one, so frnd tracks how the project moves |

Removing a source asks first, and it's permanent.

## Who Can See the Room

Open the **Members** card's **+**, or **Manage members**, to reach the **Share** sheet.

### Access

Access reads as a sentence — for example, _"Everyone with access to Garuda can view this project."_ Owners get dropdowns inside that sentence; everyone else sees the same sentence as plain text, so the rule is always legible to the people it constrains.

| Audience | Who that is |
|---|---|
| **Invited only** | Just the people on the roster |
| **Everyone with access to &lt;brand&gt;** | Anyone who can read that brand's projects |
| **Everyone in &lt;workspace&gt;** | Everyone in the workspace |

For the two wider rungs you also choose **view** or **edit**.

> **Note:** a project with no brand yet (a prospect) has no **brand** rung — only **Invited only** and the workspace.

Copying the share link tells you what the recipient will get — for example, _"Link copied · only invited people can open it."_ When a room is **Invited only**, an owner gets a one-click **Open it to &lt;workspace&gt;** shortcut on the notice.

### Members and roles

Owners can **Add member** — pick a person, pick a role, add them. Three roles exist:

| Role | Can |
|---|---|
| **Owner** | Everything, including managing access and the roster |
| **Editor** | Change the project's contents |
| **Viewer** | Read only |

Every member, whatever their role, gets a **Leave project** action on their own row.

## FAQ

**Q: Where did Activity, Recent files and the Chats list go on the Overview?**
Activity is part of **Updates & discussion** now, which shows what changed alongside the team's posts. **Chats** moved to the rail on the right. Recent files are covered by **Key work** and the **Work** tab.

**Q: I added a decision-maker in one proposal. Why is it in the other proposals too?**
In a project room, decision-makers belong to the project. Every proposal in the room shares one list, and the room shows it under **Client side**.

**Q: Why can't I post an update or a decision?**
Those need edit access to the project. Anyone who can open the room can write a post and reply.

**Q: Where did the composer at the top of the room go?**
Ask frnd from the AskFRND panel instead. On a project room it shows the project's chip, and your next new chat is filed in the project.

**Q: Is a chat I start from the project chip private?**
Yes. It's filed in the project as **Only you**, so it keeps the project's context without showing it to the team.

**Q: My teammate sees a different list of chats.**
That's expected. Everyone sees the room's shared chats plus their own private ones.

**Q: Does "Add existing" move the file into the project?**
No, it links it. Removing it from the project unlinks it again and never deletes anything.

**Q: What does the project's type change?**
Its stages, and the order of the **New** menu. A pitch also gets a proposal assistant from its brief.

**Q: Everything is greyed out and says "You have view-only access".**
You're a viewer on this project, or the room's audience capability is set to **view**. An owner can change either from the **Share** sheet.
